# Assigned subtasks and delegated draft work

Date: 2 October 2026. Status: owner-directed; implementation acceptance tracked in
BUILD_STATUS. This supersedes the pilot's duplicate-proposal default for new work.

The owner requested that the two coders implement different parts of the project,
that recommended routine decisions proceed without waiting for replies, and that
issues and draft PRs accumulate for later review. Destructive operations still
require the owner. The owner also requested economical model selection and use of
the available subscription allowance groups, then explicitly authorized official
Antigravity CLI installation.

The owner subsequently requested adding the installed local coding model. The
existing Devstral Small 2 (24B) joins as a third owner for compact tasks, with no
model download. Qwen remains coordinator; the local coder does not review itself.

## Decision

One coder owns each admitted subtask. Independent paths may run concurrently;
shared writable paths and dependencies serialize. Qwen prioritizes the bounded
backlog locally. A deterministic controller, not Qwen, enforces scope, leases,
budgets and publication authority. Tests run without network or credentials in
the existing pinned container. A fresh reviewer checks the tested proposal.
One repair may return to the same owner. Ordinary issue and draft-PR actions are
delegated; merging into the project and production deployment await later review.

Use a small capable model for focused work, explicit model/effort settings, compact
source packets, no transcript duplication and no model calls for idle polling.
Route escalation is bounded and recorded. Shared provider allowance groups must
be checked as groups; changing model names does not manufacture additional quota.
Only observed usage/reset information counts. Unknown execution outcomes retain
their claims and cannot trigger another coder call automatically.

## Initial admitted scope

Synthetic regression additions in existing AADI contract test files, linked to
the current identity/reconciliation/receiver backlog. This is a bounded first
activation of the reusable worker. It does not authorize the model to invent
business policy, access live records or silently expand the writable-file list.
More work enters through the operator-owned timestamped catalog. Empty queues
wait without inference; blocked independent tasks do not stop completed drafts.

The completed pilot and its exact Telegram publication approvals stay intact as
historical evidence. New task output uses separate supervisor branches/draft PRs
against Dev; no main update, forced push, deletion or automatic merge exists.

## Consequences

The pipeline removes duplicate implementation and repeated routine approval
round-trips. It requires actual independent-work, test, review, native CLI and
GitHub evidence before claiming unattended operation. A running laptop and its
native scheduler remain dependencies; reboot/offline continuity is separate.
